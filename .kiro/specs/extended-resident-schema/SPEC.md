# Extended Resident Schema for CSV Import

## Overview
Extend the residents table schema to support the professor's CSV format which includes additional fields for family relationships, detailed address information, gate security, and vaccination tracking.

## Problem Statement
The current database schema doesn't match the professor's CSV format:

**Current Schema:**
- id, first_name, middle_name, last_name, birth_date, gender, address, image_path, role

**Professor's CSV Format:**
- Res_ID, Res_LN, Res_FN, Res_MidN, Family_ID, House_Unit, Street, Subdivision, Gate_Color, Age, Vaccination_Count

**Missing Fields:**
1. `family_id` - Groups residents by family unit
2. `house_unit` - Specific house/unit number
3. `street` - Street name
4. `subdivision` - Subdivision/village name
5. `gate_color` - Security gate color identifier
6. `age` - Current age (can be calculated from birth_date)
7. `vaccination_count` - Number of vaccinations received

## Goals
1. ✅ Extend database schema to include all CSV fields
2. ✅ Maintain backward compatibility with existing data
3. ✅ Create specialized CSV import method for professor's format
4. ✅ Update Resident model class to include new fields
5. ✅ Preserve existing import functionality
6. ✅ Add data validation for new fields

## Requirements

### Database Schema Changes
- Add `family_id INTEGER` - Links residents in same family
- Add `house_unit VARCHAR(20)` - House/unit number (e.g., "101", "102")
- Add `street VARCHAR(200)` - Street name (e.g., "Rizal St")
- Add `subdivision VARCHAR(200)` - Subdivision/village name (e.g., "Green Valley")
- Add `gate_color VARCHAR(50)` - Gate color for security (e.g., "Red", "Blue")
- Add `vaccination_count INTEGER DEFAULT 0` - Number of vaccinations
- Keep existing `address VARCHAR(500)` for backward compatibility
- Keep existing `birth_date VARCHAR(20)` (age can be calculated)

### CSV Import Method
- Create `importResidentsFromProfessorCSV(String csvFilePath)` method
- Map CSV columns to database columns:
  - Res_ID → Skip (auto-generated)
  - Res_LN → last_name
  - Res_FN → first_name
  - Res_MidN → middle_name
  - Family_ID → family_id
  - House_Unit → house_unit
  - Street → street
  - Subdivision → subdivision
  - Gate_Color → gate_color
  - Age → Calculate birth_date (current_year - age)
  - Vaccination_Count → vaccination_count
- Construct full address from: house_unit + street + subdivision
- Handle missing/empty fields gracefully
- Return import statistics (success/failed counts)

### Model Updates
- Update `Resident.java` to include new fields
- Add getters/setters for all new properties
- Add JavaFX properties for UI binding
- Add method to get formatted full address

### Backward Compatibility
- Existing residents without new fields should display properly
- Existing CSV import method should continue to work
- UI should handle null values for new fields gracefully

## Design

### Database Migration
```sql
-- Add new columns to residents table
ALTER TABLE residents ADD COLUMN IF NOT EXISTS family_id INTEGER;
ALTER TABLE residents ADD COLUMN IF NOT EXISTS house_unit VARCHAR(20);
ALTER TABLE residents ADD COLUMN IF NOT EXISTS street VARCHAR(200);
ALTER TABLE residents ADD COLUMN IF NOT EXISTS subdivision VARCHAR(200);
ALTER TABLE residents ADD COLUMN IF NOT EXISTS gate_color VARCHAR(50);
ALTER TABLE residents ADD COLUMN IF NOT EXISTS vaccination_count INTEGER DEFAULT 0;

-- Create index for family queries
CREATE INDEX IF NOT EXISTS idx_residents_family_id ON residents(family_id);
```

### CSV Column Mapping
| CSV Column | Database Column | Transformation |
|------------|----------------|----------------|
| Res_ID | (skip) | Auto-generated by database |
| Res_LN | last_name | Direct mapping |
| Res_FN | first_name | Direct mapping |
| Res_MidN | middle_name | Direct mapping |
| Family_ID | family_id | Direct mapping |
| House_Unit | house_unit | Direct mapping |
| Street | street | Direct mapping |
| Subdivision | subdivision | Direct mapping |
| Gate_Color | gate_color | Direct mapping |
| Age | birth_date | Calculate: YYYY-01-01 where YYYY = current_year - age |
| Vaccination_Count | vaccination_count | Direct mapping |
| (computed) | address | Concatenate: house_unit + ", " + street + ", " + subdivision |
| (default) | role | "Resident" |
| (default) | image_path | Default resident image |
| (default) | gender | null (can be added later) |

### Address Construction Logic
```
Full Address = "{house_unit}, {street}, {subdivision}"
Example: "101, Rizal St, Green Valley"
```

### Birth Date Calculation
```
birth_date = (current_year - age) + "-01-01"
Example: Age 34 in 2026 → "1992-01-01"
Note: This is an approximation. Exact birth date can be updated later.
```

## Validation Rules

### Data Validation
- `family_id`: Must be positive integer or null
- `house_unit`: Max 20 characters, alphanumeric
- `street`: Max 200 characters, required for new imports
- `subdivision`: Max 200 characters, required for new imports
- `gate_color`: Max 50 characters, valid colors
- `vaccination_count`: Must be non-negative integer (0-20 range)
- `age`: Must be 0-120 for birth_date calculation

### CSV Validation
- Header row must match expected format
- Minimum required fields: Res_LN, Res_FN, Family_ID
- Age must be numeric and reasonable (0-120)
- Vaccination_Count must be numeric (0-20)
- Skip rows with missing required fields
- Log validation errors

## Risk Assessment

### Low Risk
- Adding nullable columns (won't break existing data)
- Creating new import method (doesn't affect existing functionality)

### Medium Risk
- Birth date calculation from age (approximation only)
- Address field redundancy (both full address and components)

### Mitigation
- Document that birth_date from age is approximate
- Keep both address formats for flexibility
- Add data validation to prevent invalid values
- Test thoroughly with existing database

## Notes
- The `address` field will contain the full concatenated address for backward compatibility
- Individual address components (house_unit, street, subdivision) provide more flexibility for filtering and reporting
- Age is not stored directly; it's calculated from birth_date when needed
- Family_ID enables family-based queries and reports
- Gate_Color supports security and access control features
